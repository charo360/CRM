# Environment Setup for the Mobile App

## Why this matters

`EXPO_PUBLIC_*` values are **inlined into the JS bundle when it is built**, not read
at runtime. If one is missing while a bundle is produced, the code silently falls
back to a default — usually `localhost` — and the shipped app cannot reach the
backend at all.

This bites hardest on `eas update`, which rebuilds the JS bundle and pushes it
straight to installed apps. A bare `eas update` run in a shell without these
variables will point every device on that channel at `http://localhost:8000`.

`eas build` is safe on its own, because the `env` block in `eas.json` supplies the
values. `eas update` does not read that block.

## Setup

Create a `.env` file in the `frontend` directory:

```
EXPO_PUBLIC_BACKEND_URL=https://crm-1-pnfo.onrender.com
EXPO_PUBLIC_APP_URL=https://zilo.pro
EXPO_PUBLIC_BUILD_CHANNEL=production
EXPO_PUBLIC_RC_ANDROID_KEY=goog_QgGKlpHwtYdpJXDHLTdCuGHqkmC
```

These mirror the `production` profile in `eas.json`. Expo's bundler loads `.env`
automatically for both `expo start` and `eas update`.

Then restart the dev server so the new values are picked up:

```
npx expo start --clear
```

## Publishing an over-the-air update

With `.env` in place:

```
npm run update:prod
```

That wraps `eas update --channel production --platform android`. Use
`npm run update:preview` for the preview channel.

Only JS/asset changes ship this way. Anything touching native code, the Expo SDK,
or `app.config.js` needs a full `eas build`.

## What each value does

| Variable | Used for |
| --- | --- |
| `EXPO_PUBLIC_BACKEND_URL` | Every API call, plus product and profile image URLs |
| `EXPO_PUBLIC_APP_URL` | Share links generated by the customer feedback modal |
| `EXPO_PUBLIC_BUILD_CHANNEL` | Reported through `expo-constants` for diagnostics |
| `EXPO_PUBLIC_RC_ANDROID_KEY` | RevenueCat public SDK key (safe to expose) |

## Notes

- `.env` is gitignored, so recreate it on each machine.
- To point at a local backend, add an override in `.env.local` rather than
  editing `.env` — `.env.local` wins, and is also gitignored.
- Values already set in the shell environment take precedence over `.env`, which
  is why the `eas.json` build profiles keep working unchanged.
